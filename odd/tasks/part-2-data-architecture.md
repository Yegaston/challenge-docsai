## Contract and non-goals

- Implement Part 2 in bounded, test-first work units. Separate current behavior from proposed controls; no production-safety or legal-compliance claim.
- User-selected production policy: ticket text and instructions may contain PII and still reach OpenRouter **without redaction or an extra notice/acknowledgement gate**. Legal basis, user notice and provider data-processing terms have not been validated; this risk stays open. Use synthetic data in tests and verification.
- Expire application access to tickets, instructions and analyses at 90 days from ticket creation; physically purge in retried bounded sweeps after any in-flight analysis, with an alert on backlog. Enable owner-requested deletion. Physical rows may outlive access expiry for an unbounded period during downtime or repeated lock contention; alert on backlog rather than promise a hard purge deadline. No live-row deletion can promise immediate removal from backups or retract data already sent to a provider. Avoid automatic paid retries.
- Keep logs/audit content-free; user selected metadata plus anonymized diagnostic samples. Do not ingest customer content into evaluation fixtures or assume automatic PII anonymization is reliable. Distinguish technical event retention from external log/backup operations.
- Evaluate with a versioned labeled synthetic set and human-reviewed release decision. Report wrong answers by analysis version, preserve the original, and support a same-user **demonstration** review/correction flow; this is not independent QA or a separate reviewer role.
- Keep individual review slices near the existing ≤400 changed-line target; never omit tests or compress code to fit it. ## Deletion and expiry design boundary

Owner deletion returns a conflict when that owner's analysis lock is held; the UI should explain that provider processing may continue and the user must retry. Do not cancel or claim to retract an already sent provider request. After a crash, an orphaned `running` row does not hold the session lock and may be deleted with its ticket. Use the same nonblocking lock for physical expiry: deny application reads/starts immediately at the 90-day cutoff, then skip busy owners for deletion and retry on the next bounded sweep. Apply ticket-and-analysis deletion in one database transaction, always owner-scoped; a failed query must not leave a partially deleted ticket. No deletion result promises immediate removal from backups or provider storage. This is an implementation assumption, not an independently approved legal policy.
