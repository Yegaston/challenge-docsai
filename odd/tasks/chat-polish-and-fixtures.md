# Chat Polish and Synthetic Transactions

## Objective
Polish the chat frame, composer and honest assistant progress feedback; provide authenticated customer-facing history and creation of synthetic transfer fixtures usable by the existing owner-scoped agent tools. No actual financial transaction is initiated.

## Product contract
- Enter submits a nonempty message; Shift+Enter inserts a newline. Preserve form/button submit, IME composition and keyboard accessibility. A compact send button shares the textarea row.
- On desktop, history is a left rail; on the right, messages scroll above a bottom-anchored composer within the viewport. On narrow screens, navigation/history remains reachable without hiding messages or the composer. Keep support/human-mode UX functional.
- While agent work is pending, show an accessible, visually clear activity indicator; say only that a response is being prepared. Do not imply bank access, a particular tool call, or verified transaction status before evidence exists.
- The customer can list and add clearly labeled synthetic transfer records stored in PostgreSQL under their authenticated owner ID. The server controls identity and generated record ID; input is bounded and validated, creation retry-safe, storage bounded and purgeable. Support cannot create/list customer fixtures. Existing agent tools can inspect these records; no payment API or real money movement.
- Preserve four-hour handoff, same-key chat retry, separate human replies, JWT/session behavior, no paid provider invocation without approval. Keep existing JSON/SSE contracts. Existing `.agents/` and `skills-lock.json` are user-owned untracked paths to leave untouched. Use existing feature/tracker branch chain strategy; no push/PR/merge.

## Acceptance criteria
A customer can add a bounded synthetic pending transfer for today's UTC date, find it in a clearly demo-only history, then ask the agent about it using its ID or amount/date; another customer and support account cannot access it. Repeated POST with the same request key must not duplicate a record. Chat history stays left and messages scroll above a bottom composer on desktop; Enter sends, Shift+Enter and IME work correctly, button remains clickable. Pending UI is understandable but makes no unverifiable bank claim. Existing handoff and human replies still work.
